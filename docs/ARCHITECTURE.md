# Architecture

This is the RTL in `src/`, for someone who has not seen it. The behaviour it implements is the instruction set specification ([`docs/ISA.md`](ISA.md)). Where this document and the specification differ, the specification wins.

## The idea

The chip is one programmable core. Four hardware threads take turns in a fixed rotation and share one pipeline, one memory and one register file. Thread *i* owns every cycle where `TB mod 4 = i`, where TB is a 16-bit free-running counter. So each thread runs one instruction every 4 cycles, and no thread can disturb another's timing.

A thread touches the outside world only at an event. It writes pin values into a shadow copy, then names a cycle, or an input pattern, with `tick`, `edge`, `now` or a wait. Comparators watch for that on every clock, on all four threads, whatever the pipeline is doing. When an event fires, the thread's shadow pins commit, all inputs are snapshotted and the cycle is recorded, all in that one cycle.

## The pipeline

Four stages, one thread in each. With `phase = TB[1:0]`:

| Stage | Thread | Work |
|---|---|---|
| 1 | phase + 3 | The memory cycle. Presents the address: PC for a fetch, or the `ld`/`st` address. The SRAM clocks it at the end of this cycle |
| 2 | phase + 2 | The word comes out of the SRAM and `ir3_q` captures it |
| 3 | phase + 1 | `pe_decode` decodes the word, and the register file reads two registers. Both go into stage 4 flops |
| 4 | phase | `pe_exec` executes, and every result lands at the end of this cycle |

So a word fetched in cycle *m* executes in cycle *m + 3*. Because each stage holds exactly one thread there are no hazards, no forwarding and no interlocks. A register is read in stage 3 and written in stage 4 only in that thread's own slot. A stalled instruction leaves PC alone and is simply fetched again.

T, S, D and STALE are read in stage 4, from the thread's flops, because an event in the cycle before must be visible.

Everything happens at one rising clock edge: events, the slot, the memory access and any host command all act on the flops at the start of the cycle and land at its end. Where two of them could write one flop, the order is the specification's: event, then instruction, then host. `pe_thread` writes this out in that order. The one read that sees an earlier step is `stop()`, which tests P after the event logic, so a stop in the event's own cycle sees the wait as finished.

## What is per-thread and what is shared

| Where | State |
|---|---|
| Per thread, in `pe_thread` | PC, T, D, S, LATE, STALE, ILL, RUN, P, KIND, DUE, WAITING, the armed wait (MASK, PAT, BANK, NE, TIMED, INBOX), MEM, MEM_DONE, MEM_KIND, MEM_REG, STOPREQ, STEPPING |
| Per thread, in `pe_regfile` | R0..R7 |
| Shared, one copy | TB, SYNC1, SYNC2, the pins, the mailbox, the host block |
| Shared, because each stage holds one thread | The word and its valid bit at each stage (the specification's IR and IV), the operands, and `ls_addr_q` and `ls_data_q` (MEM_ADDR and MEM_DATA for the one cycle they are needed) |

Load data takes the path of an instruction word, from the SRAM through `ir3_q` and `ir4_q`, and reaches stage 4 in the load's second slot, where it is written to the register.

D_WRITTEN from a host write has no flop. Only RUN writes D, and it also clears STALE, and in the next cycle TB cannot equal D xor 0x8000. So a surviving D_WRITTEN could change nothing.

## How a host command lands

`pe_spi` shifts bits. `pe_host` counts bytes, keeps the command and its arguments, and acts when the last argument bit arrives. Both work from SYNC2, so there is one clock domain.

A rising SCK that first shows at the pad in cycle *p* is in SYNC2 in cycle *p + 2*. In that cycle:

- the bit is taken;
- if it is the last bit of a byte, `pe_host` sees the byte;
- if it is the last argument bit of a command, the command acts. So **h = p + 2**, and the command lands after step 5 of that cycle: `pe_host` drives its strobes in cycle *h*, `pe_thread` applies them last, and instructions see the result from *h + 1*;
- MISO moves at the end of the cycle, so the pad changes in cycle *p + 3*.

Which bit is the last, and what happens at *h*:

| Command | *h* is the last bit of | At *h* |
|---|---|---|
| RUN | `start8` | Stops and starts threads |
| SETPC | `pc16` | Writes PC, or sets BUSY |
| STEP | `thread8` | Starts the step, or sets BUSY |
| POST | `data16` | Fills the word, or refuses. The result is the next reply byte |
| TAKE | The command byte | Takes the word into the reply register |
| ABORT | The command byte | Stops threads, releases `uio` pins |
| STATUS | The fourth dummy byte | Clears BUSY |
| RDREG | `reg8` | Asks for the value, or sets BUSY |
| WRMEM | Each data word | Asks for a memory cycle |
| RDMEM | `addr16`, then the high byte of each word sent, as its low byte starts | Asks for a memory cycle: the first word at `addr16`, each later one as the word before it starts its low byte |

## How the RTL meets the link rules

Sections 9.1 to 9.4 of the specification fix the link down to the cycle. This is how the RTL meets those rules, block by block. It adds no rule of its own.

- **Reply timing.** A reply byte is chosen in the cycle the last bit of the byte before it arrives, and shifted out from there. A reply that depends on the command byte is worked out from that byte as it arrives, because MISO has to move in that same cycle.
- **STATUS is not one snapshot.** Each of the 4 reply bytes is read from the flops as it is loaded, so it shows the state at the start of the cycle in which the last bit of the byte before it arrives.
- **BUSY clears at the last bit of the fourth dummy byte.** A STATUS cut short leaves BUSY set.
- **A cut command does nothing.** If CS rises before the last argument bit, the command never acts, and arguments already received are dropped.
- **Host memory access is a few cycles late.** A word waits for the first memory cycle of a stopped thread after *h*, at most 4 cycles later. The write is visible to any fetch or load after that cycle. RDMEM's data arrives 2 cycles after that memory cycle, long before the reply needs it.
- **BUSY from a memory command sets one cycle late.** The test is RUN in cycle *h + 1*, which is the state cycle *h* left.
- **A memory command that fails is dead until CS rises.** No later word in that transaction is written or read.
- **RDMEM reads ahead.** It asks for its first word as soon as `addr16` arrives, so the BUSY test is there, and for each later word as the low byte of the one before starts to shift out. Reading has no side effect, so nothing outside the link can see this.
- **RDREG takes up to 6 cycles.** It borrows port A in the stopped thread's stage 3, and takes D, S, PC and flags in that thread's stage 4. The value is in the reply register by *h + 6*, long before the reply starts, and it is the state of that cycle, not of *h*. A stopped thread can still move: STALE sets, and an event a STEP left pending fires.
- **Reset.** `rst_n` is synchronised, so internal reset ends 2 clock edges after the pad rises. Cycle 0 is the first cycle after that.
- **After CS rises** MISO returns to 0 three cycles later.

## Depth

`DEPTH` in `pe_pkg.sv` sets the memory size, through the `PE_DEPTH` macro. 512 is the SRAM. Simulation also builds 128: the same SRAM model with addresses wrapped at 128, which is enough to run everything on either depth.

What the real 128-word build still needs is a latch array in `pe_mem`, chosen by `DEPTH`: 2,048 latches through `always_latch` or explicit cells, a registered address and data, one gated write pulse per word, a 128:1 read mux 16 bits wide that shows the word in the cycle after the address as the SRAM does, and timing constraints for the latches. The pipeline does not change.

## Tests

| Where | What | How to run |
|---|---|---|
| `test/test.py` | Tests at the pins from reset under Icarus, over the real SPI link: load, start, a UART frame decoded at the pad, every host command, cut commands, BUSY and the dead memory command, all unlisted codes, bytes past a reply, a reset in mid-run, STEP and SETPC against a pending event, deadline limits and the bypass lanes. At RTL, `test_matches_simulator` runs random programs on all four threads beside the simulator in `sim/` and compares every output pin on every cycle and every reply byte. It sees only the pins, so a fault that changes hidden state without reaching a pin or a reply, such as a read taken one pipeline stage early, can pass it. At gate level, `test_netlist_matches_rtl` also runs firmware on all four threads, bypass lanes and open drain included, and compares every output pin with `pe_core` | `cd test && make`, or `make GATES=yes` with a netlist in `gate_level_netlist.v` |
| `verif/rtl_chip.py` | The RTL behind the class interface of the Python cycle simulator in `sim/`, so one bench can run on either. `ChipV2` gives the same model an env-object interface with `xfer()`; its `xfer()` is Python over the flops, and `ChipV2Pads` runs `xfer()` through the real link at the pads | `cd verif && make`, then import it from the bench. `PE_BUILD` points it at another build folder |
| `verif/tb_decode.sv` | Prints the decoder's answer for all 65,536 words, for a check against the table | `iverilog -g2012 -s tb_decode src/pe_decode.sv verif/tb_decode.sv` then `vvp` |
| `tools/gen_decode.py` | Regenerates `src/pe_decode.sv` from the table | `python3 tools/gen_decode.py docs/ISA.md` |
| `tools/estimate.sh` | Area and timing estimate: Yosys with slang and OpenSTA against the slow-corner liberty, with the SRAM as a black box and no placement | `PDK_ROOT=... tools/estimate.sh <output folder>` |

`verif/` builds two Verilator models at each depth. In `stub`, `pe_spi_stub.sv` replaces `pe_spi`, so Python can feed the last byte of a command straight into `pe_host`. The clock edge that ends a cycle is held back until something needs it, which lets a host call made after a cycle still land inside it, as it does in a byte-level simulator. In `pins`, the real `pe_spi` runs and the host works through the pads; `ChipV2Pads` uses this model. A bench that only calls `ChipV2.xfer()` tests neither `pe_spi` nor the byte logic of `pe_host`. `pe_rst` and `pe_raw_edge` in `shim.cpp` let a bench assert reset in mid-run. Verilator is 2-state, so `test/` under Icarus is what catches X problems from reset.
